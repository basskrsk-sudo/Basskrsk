# ТАЙГА — Инструкция по деплою на Amvera (сервер на Node.js)

## Что нового в v53

- **Лёгкий QR-лендинг `public/p.html`**: сканирование QR на товаре открывает
  карточку (~12 КБ) вместо всей витрины index.html на 380 КБ. Оплата
  СБП/карта за 1 минуту: телефон → ЮKassa-виджет → «забрать с полки».
- **Маршрут `/p/{точка}/{товар}`** на сервере. Старые QR вида
  `/?ref=X&product=Y` автоматически редиректятся на новый формат —
  наклеенные этикетки перепечатывать не нужно.
- **Генераторы QR** в кабинетах админа и менеджера печатают новый короткий
  формат для товарных этикеток (большой QR стойки — без изменений).
- **Новая главная `public/index-new.html`** (mobile-first, палитра
  «хвоя + золото»): точка рядом, категории, популярное из API, бонусы.
- **Mobile fixes в `index.html`**: защита от горизонтального скролла
  (`overflow-x: clip`, sticky не ломается), убраны tap-вспышка и 300 мс
  задержка, safe-area под notch, поля ввода ≥16px против iOS-зума.

## Что изменилось по сравнению со старой версией

Раньше сайт был чисто статическим (nginx + файлы), а данные (остатки, партнёры,
пароли) жили в `config.js` и `localStorage` браузера. Теперь это настоящее
серверное приложение на Node.js:

- Все данные — в базе SQLite на сервере (`/data/taiga.db`)
- Пароли партнёров/менеджеров/админа — хэшированы, не лежат открытым текстом
- Оплата — через ЮKassa (создание платежа и вебхук подтверждения — на сервере,
  с секретным ключом, которого никогда нет в браузере)
- Telegram-уведомления — тоже с сервера (надёжнее старой схемы из браузера)

**Внешних npm-зависимостей нет вообще** — сервер написан на встроенных
модулях Node.js (`node:http`, `node:sqlite`, `node:crypto`). Поэтому важно,
чтобы Amvera использовала **Node.js 22 или новее** — `node:sqlite` появился
в Node 22.5.

## ШАГ 1 — Переменные окружения (вместо части config.js)

Секретные данные теперь задаются переменными окружения на Amvera —
**не в файлах сайта**, чтобы они не попадали в браузер клиента.

В панели Amvera → раздел «Переменные окружения» добавьте:

```
YOOKASSA_SHOP_ID=ваш_shopId
YOOKASSA_SECRET_KEY=ваш_секретный_ключ
# Только для изолированного тестового стенда без реальных платежей:
# DEMO_MODE=true
# Необязательно: срок резерва 5–30 минут, по умолчанию 15:
# RESERVATION_TTL_MINUTES=15
TG_TOKEN=токен_бота_из_BotFather
TG_CHAT_ID=ваш_chat_id
# Текущий адрес бота без @. Меняйте только после смены username в BotFather:
TG_BOT_USERNAME=taiga_dog_bot
TOKEN_SECRET=любая_длинная_случайная_строка_для_подписи_токенов_входа
```

### Telegram-бот «ХвостМаркет»

При запуске сервер автоматически устанавливает отображаемое имя
«ХвостМаркет», фирменное описание и команды `/start` и `/help`. Тексты входа
и уведомлений также формируются под новым брендом.

В старых сборках токен Telegram по ошибке находился в публичном `config.js`.
Перед публикацией этой версии обязательно откройте `@BotFather`, перевыпустите
токен бота и замените значение `TG_TOKEN` в переменных Amvera. Старый токен
после перевыпуска перестанет работать.

Username бота не меняется кодом, потому что это его фактический адрес. Если
вы выберете новый свободный username в BotFather, после этого укажите его без
символа `@` в переменной `TG_BOT_USERNAME`, иначе ссылки входа будут вести по
старому адресу. Квадратную пиктограмму «лапка на геоточке» для аватара можно
взять из `public/images/icons/icon-512.png` и установить через BotFather.

**Как получить ключи ЮKassa:**
1. Зарегистрируйтесь на yookassa.ru как ИП
2. Личный кабинет → Настройки → API → скопируйте `shopId` и `Секретный ключ`
3. В личном кабинете ЮKassa укажите адрес для вебхуков:
   `https://ваш-домен/api/yookassa-webhook`

**COMPANY_INN / COMPANY_OGRNIP** и прочие несекретные настройки (название
бренда, город, реквизиты для договора с партнёрами) остаются в `public/config.js`,
как и раньше — это публичная информация, ей не место в переменных окружения.

### Почта (SMTP) — обязательно для восстановления пароля клиентов

Клиенты теперь входят либо через Telegram, либо по паролю (без SMS), а
забытый пароль восстанавливают по ссылке на почту. Без настроенной почты
восстановление молча не работает (сайт не покажет ошибку, письмо просто не
уйдёт) — обязательно добавьте:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=ваш_ящик@yandex.ru
SMTP_PASSWORD=пароль_приложения_(не обычный пароль от почты)
```

Та же настройка уже используется для ежедневного бэкапа базы и уведомлений —
если она у вас уже была задана раньше, ничего дополнительно делать не нужно.

## ШАГ 2 — Персистентное хранилище (важно!)

База данных (SQLite) должна жить в папке `/data` — это специальная папка
Amvera, которая **не стирается** при пересборке приложения (в отличие от
папки с кодом, которая пересоздаётся заново при каждом деплое).

В конфигурации приложения на Amvera убедитесь, что:
- `persistenceMount` указывает на `/data` (это значение по умолчанию, менять
  не нужно, если не меняли раньше)
- Первый деплой обязательно должен пройти успешно один раз — после этого
  папка `/data` появится и данные будут сохраняться между обновлениями

Если вы вообще не настраивали `persistenceMount` — Amvera использует `/data`
по умолчанию, ничего дополнительно делать не нужно.

## ШАГ 2.5 — Резервная копия базы ПЕРЕД каждым обновлением (рекомендуется)

База данных живёт в одном файле `/data/taiga.db` — там всё сразу: заказы,
товары, клиенты, партнёры, косточки. Сама заливка новой версии код не
трогает, но перед любым обновлением стоит перестраховаться:

1. Зайдите в `taiga-admin.html`, раздел «Дашборд»
2. Найдите карточку «💾 Резервная копия базы данных»
3. Нажмите **«⬇️ Скачать бэкап сейчас»** — файл `taiga-backup-....db` скачается
   прямо на компьютер (это безопасный, консистентный снимок базы через
   встроенный механизм SQLite — можно смотреть его позже в любой
   программе для просмотра SQLite, например DB Browser for SQLite)
4. Только после этого заливайте новую версию

Рядом есть вторая кнопка «Отправить на почту сейчас» — то же самое, но
письмом (нужен настроенный `BACKUP_EMAIL`/`BUSINESS_COPY_EMAIL`); плюс
автоматическая копия и так уходит на почту раз в сутки без вашего участия.
Кнопка «Скачать» ни от чего не зависит и работает всегда.

Для восстановления супер-администратору доступна кнопка «Восстановить из
файла». Выберите ранее скачанный файл `.db` и подтвердите действие. Сервер
проверит, что это целая база «Тайги», автоматически сохранит текущую базу в
`/data/taiga-before-restore-....db`, затем перезапустится и установит выбранную
копию. Обычным администраторам эта кнопка не показывается.

Если автоматический перезапуск на Amvera отключён, после загрузки файла
перезапустите приложение вручную — подготовленная копия установится при старте.

## ШАГ 3 — Деплой

1. Загрузите на Amvera все файлы из этой папки (`Dockerfile`, `package.json`,
   `server/`, `public/`) — так же, как раньше загружали статику
2. Нажмите «Собрать и задеплоить»
3. Дождитесь статуса «Работает»
4. При первом запуске сервер сам создаст базу данных и заполнит её начальными
   данными (3 точки, 11 товаров, админ с логином `admin` / паролем `taiga2025#`)
5. **Сразу смените пароль администратора** — зайдите в `taiga-admin.html`,
   войдите со стандартными данными, потом либо через код, либо попросите
   помочь сменить пароль на сервере

## ШАГ 4 — Проверка

- Откройте `https://ваш-домен/` — каталог должен загрузиться (теперь из базы,
  не из захардкоженного списка)
- Откройте `https://ваш-домен/taiga-admin.html`, войдите как админ, проверьте
  разделы «Товары», «Заказы», «Точки», «Менеджеры»
- Сделайте тестовый заказ на сайте. Без `YOOKASSA_SHOP_ID` и
  `YOOKASSA_SECRET_KEY` оплата безопасно блокируется и заказ не создаётся.
- Для изолированного тестового стенда демо-оплату можно включить явно переменной
  `DEMO_MODE=true`. Никогда не задавайте её в боевой среде.
- Проверьте двумя параллельными попытками, что последняя единица товара и один
  баланс косточек доступны только одному заказу. Неоплаченный резерв снимается
  через 15 минут после безопасной отмены платежа в ЮKassa.

## Если что-то не работает

**«Cannot find module node:sqlite» или похожая ошибка**
→ Проверьте версию Node.js на Amvera — нужна 22.5 или новее. Если Amvera
предлагает более старую версию в конфигурации окружения, обновите её.

**Данные пропадают после каждого обновления сайта**
→ Значит `/data` не смонтирована как постоянное хранилище — проверьте
`persistenceMount` в конфигурации приложения (см. Шаг 2)

**Оплата не проходит / вебхук не приходит**
→ Проверьте, что в личном кабинете ЮKassa указан правильный адрес вебхука
(`https://ваш-домен/api/yookassa-webhook`) и что сайт работает по HTTPS

**Telegram-уведомления не приходят**
→ Проверьте `TG_TOKEN`/`TG_CHAT_ID` в переменных окружения (не в config.js!)
и что вы написали боту `/start`
